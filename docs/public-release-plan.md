# 首次公开发布计划

基线为私有仓库 main 的 d45f1f1。建议首发为 GitHub Release v0.1.0，优先支持已验证的 WSL、dsh-tui 0.20.2 和 agy 1.5.13。核心验收场景是另一位已有官方 CLI 的用户，从公开发布页出发，在干净 profile 里独立完成安装、登录、第一轮对话、查询配额和卸载。宿主界面展示 C 版吉祥物作为独立验收项。

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| 1. 确定可公开的内容 | 检查所有待公开分支、标签和历史，包括当前 main 的 12 个提交。核对凭据、个人路径、终端截图、作者信息、测试数据和二进制补丁。项目代码采用维护者已确认的 MIT 许可证，发布时补齐许可证文件与清单，并保留宿主补丁相关的上游版权说明。单独核对参考图、生成的吉祥物、预览图的公开分发依据，标明社区项目身份。 | 列出公开清单及需替换内容，维护者确认待处理的素材方案。有不宜公开的历史时，提出保留现有私库、另建干净公开仓库的选项。 |
| 2. 固定安装方式 | 优先验证 dsh 能直接安装 GitHub Release 的固定版本包。若宿主不支持该输入，提供经验证的固定标签下载、解压、安装命令及稳定安装目录。用实际打包清单核对 JS、Cordis 和插件清单、UI 资源、许可证与依赖。 | 从候选发布物即可完成安装；用户无需开发者目录、GitHub 凭据或本项目的 npm 发布账号。明确插件、宿主和 agy 的各自安装前提。 |
| 3. 整理对外文档 | README 首屏放用途、终端实图、兼容组合、安装命令和首次使用。说明已有 agy 账号的复用与首次登录，给出 /usage、恢复会话、启用主题及先撤销 UI 再卸载插件的路径。现有长篇验收证据移至详细文档。注明双真实账号切换和其他平台的验证状态。 | 新用户按顺序复制命令即可走通。遇到宿主版本不匹配时，可保留默认 UI 使用后端。 |
| 4. 从发布物验收 | 用临时 HOME 和全新 dsh profile 安装候选包，检查 29 项现有回归、首次启动、真实对话、/usage、会话恢复、UI 安装与撤销、重复安装、旧版升级、卸载后原内核可用。缺少 agy 和宿主版本不符分别检查提示。将无需真实账号的测试和打包检查接入 CI；真实 Google 登录及模型调用独立验收。 | 记录候选提交、包校验值、平台与版本、通过项和已知限制。兼容性声明只列实际跑过的组合。 |
| 5. 发布与复验 | 先准备标签、Release 文案和安装包，向维护者展示将公开的仓库、历史及资产；获得最终确认后公开并发布。通过无 GitHub 登录态的环境下载正式附件，复跑公开安装步骤。提供问题反馈入口，收集宿主、agy、平台和终端版本，提醒用户去除授权链接。 | 外部用户能从公开链接下载并完成最短流程。记录后续升级与回退方式。 |

后续按实际需求追加 npm 分发、原生 Windows/macOS 验收，并向宿主提出插件品牌扩展接口。当前 package.json 的 private 标记可在 GitHub 首发时保留。品牌补丁只针对 0.20.2，宿主升级时单独核对。

代码许可证已确定为 MIT。剩余维护者决策点为来源未明素材的处理和最终公开动作。若选择 npm 发布，再安排包名、发布身份及账户验证。
